# Рабочий Neovim на nvf

Компактная сборка для разработки, а не копия LazyVim. Nix устанавливает плагины,
парсеры и конфигурацию. Нет lazy.nvim, Mason, Extras, отдельного lazy-lock.json
и скачиваний при запуске редактора. Версии закреплены в `nixos/flake.lock`.
Даже опциональная ленивая загрузка nvf отключена.

## Что где настраивается

- `default.nix` — подключение Home Manager, пакет `neovim` и проверки.
- `settings/editor.nix` — параметры редактора, completion и Treesitter.
- `settings/ui.nix` — тема, интерфейс, dashboard и Git.
- `settings/languages.nix` — LSP-хоткеи и форматирование.
- `config/lua/work/dashboard.lua` — содержимое и раскладка первого экрана.
- `config/lua/work/keymaps.lua` — основные хоткеи и команда `:Tools`.
- `config/lua/work/lsp.lua` — подключение доступных языковых серверов.
- `config/lua/work/tools.lua` — поиск инструментов в окружении проекта.
- `devenv.nix` в проекте — компиляторы, LSP, форматтеры и линтеры этого проекта.

Сохранены тема Zed macOS Classic Dark, Space в качестве leader, поиск файлов и
текста, explorer, буферы, терминал, Git, completion со snippets, переходы по коду,
переименование и форматирование при сохранении. Базы данных, отладчики и sessions
не включены.

## Первый экран

`nvim` без аргументов открывает dashboard: логотип, быстрые действия, недавние
файлы и проекты, текущий каталог и индикатор devenv. На широком экране — две
колонки, на небольшом — компактная вертикальная раскладка. История хранится
обычным ShaDa Neovim; при первом запуске вместо пустых списков видны подсказки.

Клавиши на стартовом экране: `f` — файлы, `n` — новый файл, `g` — поиск текста,
`r` — недавние файлы, `p` — проекты, `e` — explorer, `t` — инструменты, `q` — выход.
`Space uD` открывает dashboard из редактора. Запуск `nvim файл` сразу открывает
файл, без dashboard. Новых плагинов, shell-скриптов и сетевых запросов экрану не
требуется.

Выбор другого проекта в dashboard не меняет окружение процесса. Если ему нужно
другое devenv, запустите отдельный `nvim` из окружения того проекта.

## Запуск

После обычного применения NixOS/Home Manager запускайте `nvim` из окружения
проекта: через direnv или после `devenv shell`. Для каждого проекта лучше
запускать отдельный процесс редактора: смена каталога внутри Neovim не меняет
его окружение.

LSP подключаются только при наличии соответствующей команды в окружении.
Нативный TypeScript 7 имеет приоритет; локальный TS 5 не скрывает его в PATH.
Если TS 7 отсутствует, используется `typescript-language-server`, если он
предоставлен проектом. Для Astro/Svelte нужен соответствующий отдельный LSP;
TypeScript SDK остаётся локальной зависимостью приложения.

Форматирование: Prettier из проекта, Biome при наличии его конфигурации;
Astro/Svelte используют Prettier с плагинами проекта. Go — goimports и
gofumpt/gofmt, Python — Ruff или Black. Если инструмент отсутствует, редактор
не пытается его установить и по возможности форматирует через LSP.
`:Tools` показывает найденные LSP; `:ConformInfo` — форматтеры.

Проектные `.lazy.lua` больше не читаются и не нужны для обычной работы.
Старые файлы и кеши LazyVim в домашнем каталоге не удаляются, но новая сборка
использует отдельный `NVIM_APPNAME=nvf` и не читает старый `~/.config/nvim`.
Команда для запуска при этом по-прежнему `nvim`.

## Основные клавиши

| Клавиши | Действие |
| --- | --- |
| `Space Space`, `Space ff` | Файлы проекта |
| `Space /`, `Space sg` | Поиск текста |
| `Space e`, `Space ,` | Explorer, буферы |
| `Shift-h`, `Shift-l` | Предыдущий/следующий буфер |
| `gd`, `gr`, `gI`, `gy` | Определение, ссылки, реализация, тип |
| `K`, `gK` | Документация, сигнатура |
| `Space ca`, `Space cr` | Code action, переименование |
| `Space cf`, `Space uf` | Форматировать, переключить автоформатирование |
| `Space cd`, `[d`, `]d` | Диагностика |
| `Space gg`, `[h`, `]h` | Lazygit, Git hunks |
| `Space ft`, `Ctrl-/` | Терминал |
| `Space sk`, `Space sh` | Все хоткеи, справка |
| `Space uD` | Стартовый экран |
| `:Tools` | Инструменты текущего окружения |

## Проверить без пересборки системы

Из корня dotfiles:

```sh
nix run path:./nixos#neovim
nix build path:./nixos#checks.x86_64-linux.neovim
nvim --headless -u NONE -l nixos/modules/development/neovim/tests/unit.lua
```

Проверка включает настоящий TUI в псевдотерминале: автозапуск dashboard,
адаптацию к размеру окна, быстрые действия и открытие файлов без dashboard.
Для проверки реальных LSP и форматирования из каталога проекта с devenv:

```sh
devenv shell -- bash /path/to/dotfiles/nixos/modules/development/neovim/tests/smoke.sh
```

`path:` позволяет проверить новые файлы ещё до добавления в Git. Перед обычным
Git-flake rebuild добавьте изменения в Git. Чтобы обновить сборку и плагины:
`nix flake update nvf --flake ./nixos`, затем обычный rebuild. Обновление nixpkgs
также обновляет плагины, которые сборка берёт из него.
