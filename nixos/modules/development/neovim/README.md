# Рабочий Neovim на nvf

Сборка для разработки, а не копия LazyVim. Nix устанавливает плагины,
парсеры, LSP и конфигурацию. Форматтеры и toolchain предоставляет окружение проекта.
Нет lazy.nvim, Mason, Extras, отдельного lazy-lock.json
и скачиваний при запуске редактора. Версии закреплены в `nixos/flake.lock`.
Даже опциональная ленивая загрузка nvf отключена.

## Что где настраивается

- `default.nix` — подключение Home Manager и пакет `neovim`.
- `settings/editor.nix` — параметры редактора, completion и Treesitter.
- `settings/ui.nix` — тема, интерфейс и Git.
- `settings/keymaps.nix` — все хоткеи, группы WhichKey и события редактора.
- `settings/dashboard.nix` — логотип, меню, подписи и секции первого экрана.
- `settings/languages.nix` — декларативные настройки LSP, диагностики и форматирования.
- `devenv.nix` в проекте — форматтеры, компиляторы, рантаймы и сервисы приложения.

Сохранены тема Zed macOS Classic Dark, Space в качестве leader, поиск файлов и
текста, explorer, буферы, терминал, Git, completion со snippets, переходы по коду,
переименование и форматирование при сохранении. Базы данных, отладчики и sessions
не включены.

## Первый экран

`nvim` без аргументов открывает dashboard: логотип, быстрые действия, недавние
файлы и проекты. Это штатные секции Snacks, описанные в `settings/dashboard.nix`,
без собственного Lua-модуля и динамических функций. На широком экране — две
колонки, на узком Snacks объединяет их в одну. История хранится обычным ShaDa
Neovim; пустые секции автоматически скрываются.

Клавиши на стартовом экране: `f` — файлы, `n` — новый файл, `g` — поиск текста,
`r` — недавние файлы, `p` — проекты, `e` — explorer, `t` — состояние LSP, `q` — выход.
`Space uD` открывает dashboard из редактора. Запуск `nvim файл` сразу открывает
файл, без dashboard. Новых плагинов, shell-скриптов и сетевых запросов экрану не
требуется.

Выбор другого проекта в dashboard не меняет окружение процесса. Если ему нужно
другое devenv, запустите отдельный `nvim` из окружения того проекта.

## Запуск

После обычного применения NixOS/Home Manager запускайте `nvim` из каталога
проекта. Языковые серверы включены в пакет редактора штатными модулями nvf
в `settings/languages.nix` и запускаются по абсолютным путям из Nix store.
Устанавливать LSP в devenv или настраивать проектный Lua-файл не нужно.

Для форматтеров и проектной toolchain используйте direnv/devenv: например,
Go для gopls, Cargo/Rust для rust-analyzer, Python с зависимостями приложения.
Это окружение не подменяет бинарники LSP редактора.

TypeScript использует отдельный нативный TS7 LSP из Nix, Python — BasedPyright
и Ruff. TypeScript 5.9.3 остаётся SDK приложения для Astro/Svelte-проверок;
он не заменяется на TS7. Диагностика TS7 в редакторе может отличаться от TS5
при проверке проекта. `ts_ls` параллельно не запускается, обёртка `tsgo` не нужна.

Astro/Svelte используют отдельные LSP. TypeScript SDK приложения остаётся
зависимостью проекта. Prettier и его плагины Astro/Svelte берутся из проекта;
Go использует goimports и gofumpt, Python — Ruff, Nix — nixfmt, Lua — StyLua.
Conform разрешает команды стандартным способом, без собственных Lua-функций.
Автоформатирование при сохранении управляется штатным механизмом nvf.
`:checkhealth vim.lsp` показывает состояние LSP; `:ConformInfo` — форматтеры.

Форматтеры Nix/Lua установлены глобально через Home Manager в
`modules/development/tools.nix`: для работы с dotfiles отдельный devenv не нужен.
Остальные форматтеры добавляйте в окружение соответствующего проекта.

Проектные `.lazy.lua` больше не читаются и не нужны для обычной работы.
Старые файлы и кеши LazyVim в домашнем каталоге не удаляются, но новая сборка
использует отдельный `NVIM_APPNAME=nvf` и не читает старый `~/.config/nvim`.
Команда для запуска при этом по-прежнему `nvim`.

## Основные клавиши

| Клавиши | Действие |
| --- | --- |
| `Space Space`, `Space ff` | Файлы проекта |
| `Space /`, `Space sg` | Поиск текста |
| `Space e`, `Space ,` | Explorer, буферы |
| `Shift-h`, `Shift-l` | Предыдущий/следующий буфер |
| `gd`, `gr`, `gI`, `gy` | Определение, ссылки, реализация, тип |
| `K`, `gK` | Документация, сигнатура |
| `Space ca`, `Space cr` | Code action, переименование |
| `Space cf`, `Space uf` | Форматировать, переключить автоформатирование |
| `Space cd`, `[d`, `]d` | Диагностика |
| `Space gg`, `[h`, `]h` | Lazygit, Git hunks |
| `Space ft`, `Ctrl-/` | Терминал |
| `Space sk`, `Space sh` | Все хоткеи, справка |
| `Space uD` | Стартовый экран |
| `Space cl` | Состояние LSP |

## Попробовать без пересборки системы

Из корня dotfiles:

```sh
nix run path:./nixos#neovim
```

`path:` позволяет проверить новые файлы ещё до добавления в Git. Перед обычным
Git-flake rebuild добавьте изменения в Git. Чтобы обновить сборку и плагины:
`nix flake update nvf --flake ./nixos`, затем обычный rebuild. Обновление nixpkgs
также обновляет плагины, которые сборка берёт из него.
